# 本仓库运行制度:Loong Workflow 实例

> 本项目的一切变更走工单迭代。制度源:Loong Workflow(语料库部署于 Loong Gitea)。
> 工单板:http://39.108.95.179:3000/kenyang/wechat-ops/issues

## 路由表(什么改动走什么流程)

| 改动类型 | 流程 | 关单条件 |
|---|---|---|
| 新功能(feat) | 工单 → 实现 → 服务器实测验证 → 证据评论 → 关闭 | 验收标准全过 + 眼见确认 |
| bug 修复 | 工单(附复现证据) → 修复 → 回归测试 → 关闭 | 修复前失败/修复后通过的实测记录 |
| 文档 | 直接改 → 守卫 → 推送 | — |
| 小发现/技术债 | **TD 登记册**(#1)加登记行,不单开工单 | 认领时才升票 |

## 工单约定(继承 Loong Workflow)

- 父子工单双向链接:子工单正文带 `## Parent`
- 技术债先登记(#1 登记册,TD-NNN 行),认领升票
- 关单即归档:证据评论里写清 实测时间/结果/日志位置
- 诚实红线:没有眼见确认不写"已验证";错误关票要发状态修正评论(实例:2026-09-29 #6/#7/#8/#9 误关纠正)

## 发布流程

1. 本地/服务器改 agent.py → 服务器 py_compile → 部署实测
2. 回填本仓库 scripts/ → CHANGELOG 版本条目
3. 双远端推送:origin(GitHub) + loong(Loong Gitea)
4. 重建分发包 wechat-gui-agent-skill.tar.gz(OneDrive zcode)
5. 跑 scripts/check-skill.sh 守卫(如涉及 skill 结构)
